2. MECANISME CHOISI PAR RESSOURCE
--------------------------------------------------------------
 Ressource            Mecanisme                       Pourquoi
 -------------------  ------------------------------  -----------------
 Portes               Semaphore compteur (= nb de     Le semaphore dit
                      portes libres) + mutex pour     "il reste une
                      "chercher + reserver" en un     porte" ; le mutex
                      seul bloc                       evite le conflit
 Table d'etat vols    Mutex (sections tres courtes :  Simple, rapide ;
                      copier/ecrire une structure)    pas d'IA sous verrou
 File d'evenements    Moniteur = mutex + 2 variables  Attente passive
                      de condition (non_vide,         du consommateur,
                      non_pleine), taille bornee 16   pas d'attente active
 Bus de transfert     Semaphore compteur (valeur      sem_wait = prendre
                      initiale 3 ou 5)                un bus, sem_post =
                                                      le rendre
 Console / journal    Mutex (ou un seul thread        Lignes lisibles
                      d'ecriture)

Regles :
  - Sections critiques tres courtes : jamais d'inference IA (T3,
    30 ms) ni de calcul long sous verrou. (La demo garde 1 ms
    sous verrou volontairement pour montrer qu'il protege.)
  - Ordre fixe si plusieurs verrous (ex. portes avant vols) pour
    eviter l'interblocage (deadlock).
  - Pas de printf long sous un verrou critique.

--------------------------------------------------------------
4. COMPILATION, EXECUTION, OBSERVATIONS
--------------------------------------------------------------
Compilation :
  gcc -O0 -Wall -pthread m4_sans_sync.c -o m4_sans_sync
  gcc -O0 -Wall -pthread m4_avec_sync.c -o m4_avec_sync
  gcc -O0 -Wall -pthread m4_bus_sem.c   -o m4_bus_sem

Execution :
  ./m4_sans_sync
  ./m4_avec_sync
  ./m4_bus_sem

Que observer (et copier dans le rapport) :

 m4_sans_sync :
   - Avion A et Avion B affichent tous les deux "Porte 2 est libre"
     AVANT que l'un des deux ait reserve.
   - Puis "Avion A : reserve Porte 2" et "Avion B : reserve Porte 2".
   - Ligne "=> CONFLIT : Porte 2 attribuee a 2 vols".
   - Bilan attendu : conflits sur 5 essais sur 5 (le delai de 1 ms
     force la situation ; sans lui le conflit est possible mais
     non deterministe).

 m4_avec_sync :
   - Avion A : "reserve Porte 2" ; Avion B attend le verrou, puis
     "Porte 2 non disponible (occupee), suivante" et
     "reserve Porte 3".
   - "=> OK : aucune porte attribuee deux fois" a chaque essai.
   - Bilan : 0 conflit sur 5 essais.
   - Test supplementaire : NB_VOLS = 3 -> Avion C affiche
     "aucune porte libre -> file d'attente" (le semaphore vaut 0).

 m4_bus_sem :
   - 3 groupes montent tout de suite (bus utilises 1/3, 2/3, 3/3),
     les 3 autres attendent.
   - Apres ~300 ms, des bus sont liberes et les groupes suivants
     montent.
   - "Max de bus utilises en meme temps : 3 (limite 3) -> OK".
   - Duree totale ~600 ms contre 1800 ms en sequentiel.
   - Refaire avec NB_BUS = 5 : 5 groupes partent tout de suite,
     le 6e attend ~300 ms -> duree totale ~600 ms (2 vagues).
     Avec NB_BUS = 6 : ~300 ms (1 seule vague).

Un seul essai ne suffit pas : lancer plusieurs fois, garder
une capture de chaque sortie pour le rapport.
